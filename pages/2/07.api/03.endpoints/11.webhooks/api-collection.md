Register outgoing HTTP webhooks that fire when API write events happen (page/media/user mutations, config updates, GPM installs, Grav upgrades). Each webhook has a URL, an event filter list, optional custom headers, a generated secret for HMAC signing, and a delivery log.

Permissions: `api.webhooks.read` / `api.webhooks.write`. Secrets are generated by the server and always redacted in API responses, except once in the response that creates the webhook.

## Valid event names

`*` (all), `page.created`, `page.updated`, `page.deleted`, `page.moved`, `page.translated`, `pages.reordered`, `media.uploaded`, `media.deleted`, `user.created`, `user.updated`, `user.deleted`, `config.updated`, `gpm.installed`, `gpm.removed`, `grav.upgraded`.

## Deliveries

Each delivery is a JSON `POST` of `{"event": "...", "timestamp": "<ISO 8601>", "data": {...}, "webhook_id": "wh_..."}`. Grav adds these headers to every delivery:

| Header | Value |
|--------|-------|
| `X-Grav-Signature` | Hex HMAC-SHA256 of the raw request body, keyed with the webhook's secret |
| `X-Grav-Event` | The webhook event name, e.g. `page.updated` |
| `X-Grav-Delivery` | A unique delivery ID (`dlv_...`) |

A webhook's custom `headers` can set other headers, including `Content-Type` and `User-Agent`, but can't replace these three: creating or updating a webhook with one of them returns `422`. Only `http` and `https` URLs are accepted, and a URL that resolves to a private, loopback, link-local or reserved address is refused, both when saved and again at delivery time. Redirects are not followed.

A webhook that fails 5 deliveries in a row is disabled automatically, with a `disabled_reason`; a successful delivery resets the count. The last 50 deliveries of each webhook are kept.
